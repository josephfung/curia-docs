title: "Enable semantic memory with OpenAI embeddings"
sidebarTitle: "OpenAI embeddings"

---

Curia's knowledge graph needs an embedding model to build semantic memory: relationships between people, projects, and topics that persist across conversations. OpenAI's `text-embedding-3-small` is one option. You can also [use your own embedding server](/integrations/embeddings-endpoint) instead.

Embeddings are optional, but without an embedding source the knowledge graph is off. Entity memory, semantic search and the features that depend on them are unavailable until you add one.

## Get an OpenAI API key

<Steps>
  <Step title="Create an account at platform.openai.com">
    Go to [platform.openai.com](https://platform.openai.com) and sign in or create an account.
  </Step>

  <Step title="Generate an API key">
    Under **API keys**, click **Create new secret key**. Copy it immediately — it is only shown once.
  </Step>

  <Step title="Add billing">
    Embedding calls are low-cost but require a payment method. Add one under **Billing → Payment methods**. A few dollars of credit covers typical usage for months.
  </Step>
</Steps>

## Add the key to the vault

<Steps>
  <Step title="Store the key as openai_api_key">
    ```bash
    docker compose run --rm \
      -e SEED_VAULT_ONLY=openai_api_key \
      -e OPENAI_API_KEY=sk-... \
      curia ./node_modules/.bin/tsx scripts/seed-vault.ts
    ```

    From a source checkout, run `SEED_VAULT_ONLY=openai_api_key OPENAI_API_KEY=sk-... pnpm run seed-vault` instead.
  </Step>

  <Step title="Restart Curia">
    ```bash
    docker compose restart curia
    ```

    Curia reads the vault at startup, so the key takes effect after the restart.
  </Step>
</Steps>

Leave `EMBEDDING_BASE_URL` unset in `.env`. When it is unset, Curia uses OpenAI and the `openai_api_key` vault entry.

## What changes after connecting

Curia begins building entity nodes for people you mention, projects you discuss, and topics that recur. Over time this creates a network of relationships that informs research, drafting, and scheduling. The change is gradual — you won't notice it immediately, but it compounds over weeks of use.

## Switch to another model later

If you move from OpenAI to your own server after the knowledge graph has stored vectors, you need to re-embed the graph once. See [Change models](/integrations/embeddings-endpoint#change-models).
