Curia's knowledge graph runs on an embedding model [bundled in the image](/integrations/embeddings-endpoint), with no key needed. OpenAI's `text-embedding-3-small` is one alternative. Curia treats OpenAI like any other embedding server: you set its address and model in `.env`, and its key in the vault.

Choose OpenAI if you'd rather use a hosted model than the bundled one. Every knowledge-graph label, sensitive facts included, is then sent to OpenAI, and each embedding is billed.

<Note>
  This page describes releases after v0.45.0. On v0.45.0 and earlier, `openai_api_key` alone is the normal way to use OpenAI, not a deprecated one; see [Search and memory](/get-started/search-and-memory).
</Note>

## Get an OpenAI API key

<Steps>
  <Step title="Create an account at platform.openai.com">
    Go to [platform.openai.com](https://platform.openai.com) and sign in or create an account.
  </Step>

  <Step title="Generate an API key">
    Under **API keys**, click **Create new secret key**. Copy it immediately — it is only shown once.
  </Step>

  <Step title="Add billing">
    Embedding calls are low-cost but require a payment method. Add one under **Billing → Payment methods**. A few dollars of credit covers typical usage for months.
  </Step>
</Steps>

## Point Curia at OpenAI

<Steps>
  <Step title="Set OpenAI as the endpoint in .env">
    ```env
    EMBEDDING_BASE_URL=https://api.openai.com/v1
    EMBEDDING_MODEL=text-embedding-3-small
    ```
  </Step>

  <Step title="Store the key as embedding_api_key">
    ```bash
    docker compose run --rm \
      -e SEED_VAULT_ONLY=embedding_api_key \
      -e EMBEDDING_API_KEY=sk-... \
      curia ./node_modules/.bin/tsx scripts/seed-vault.ts
    ```

    From a source checkout, run `SEED_VAULT_ONLY=embedding_api_key EMBEDDING_API_KEY=sk-... pnpm run seed-vault` instead.
  </Step>

  <Step title="Start Curia with the new settings">
    ```bash
    docker compose up -d curia
    ```

    On a fresh install, or one whose knowledge graph holds no vectors yet, that's all. If the graph already holds vectors from the bundled model or another one, re-embed it before starting Curia: see [Switch models](/integrations/embeddings-endpoint#switch-models).
  </Step>
</Steps>

The boot log line `Entity memory initialized with knowledge graph` then shows `"embeddingSource":"endpoint"` and `"embeddingModel":"text-embedding-3-small"`.

## Older installs: the implicit OpenAI default

Before the bundled model, an install with no `EMBEDDING_BASE_URL` and an `openai_api_key` in the vault used OpenAI automatically. Such an install keeps working after the upgrade, because its knowledge graph holds `text-embedding-3-small` vectors and Curia never switches an install's model on its own.

That path is **deprecated** and a later release removes it. While it applies, Curia logs a deprecation warning at boot, and `/api/health` reports `knowledge_graph: ok` with `details.knowledge_graph: "implicit_openai_deprecated"`. Before the removal, pick one:

- **Keep OpenAI.** Follow [Point Curia at OpenAI](#point-curia-at-openai) above, using the same OpenAI key. No re-embed is needed: the stored vectors already come from `text-embedding-3-small`. The warning stops after the restart.
- **Switch to the bundled model.** Set `EMBEDDING_MODEL=all-MiniLM-L6-v2` and re-embed. See [Switch models](/integrations/embeddings-endpoint#switch-models).

`openai_api_key` stays in use for image generation either way.

## What changes after connecting

Curia begins building entity nodes for people you mention, projects you discuss, and topics that recur. Over time this creates a network of relationships that informs research, drafting, and scheduling. The change is gradual — you won't notice it immediately, but it compounds over weeks of use.
