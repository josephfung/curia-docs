## Upgrade notes

Updating Curia pulls new images and runs migrations on startup (see [Updating Curia](/get-started/installation#updating-curia)). Some releases also need a change that an update never makes for you, because `install.sh` never edits an existing `docker-compose.yml`. Those changes are listed here, newest first.

### Upgrading to edge/v0.46

Fresh installs now default to HTTPS and turn voice on. An update changes neither for an install you already have. Work through this list if you run voice, or want to.

1. **Turn voice on, if you want calls.** An update leaves LiveKit off, and `install.sh` says so when you re-run it. Follow [Turn voice on for an existing install](/channels/voice-setup#turn-voice-on-for-an-existing-install): fetch the new compose file, Caddyfile and both LiveKit configs, generate keys into `.env`, and enter the same values in **Settings → Channels → Voice**.
2. **Set real keys before using the new HTTPS compose file.** With the new `docker-compose.tls.yml`, LiveKit no longer falls back to `--dev` when `LIVEKIT_COMMAND` is unset. It refuses to start until `LIVEKIT_KEYS` holds a real key pair. If you run voice on an HTTPS install that relied on that fallback, set `LIVEKIT_KEYS` and `LIVEKIT_COMMAND="--config /etc/livekit.yaml"` in `.env` first, and enter the same key pair in **Settings → Channels → Voice**.
3. **Running Curia outside Docker?** Curia now joins its own end of each call over `ws://livekit:7880` on the compose network. Installs where Curia runs in Docker need no change. If Curia runs directly on the host, set `LIVEKIT_INTERNAL_URL` (for example `ws://localhost:7880`) in its environment.

### Upgrading to v0.45

Back up the database first. Then work through this list.

1. **Keep Postgres on loopback.** Edit the postgres `ports:` entry to read `- "${POSTGRES_BIND:-127.0.0.1}:${POSTGRES_PORT:-5432}:5432"`, then run `docker compose up -d postgres` so the container is recreated. An edit alone changes nothing. On an HTTPS install, also change the curia entry to `- "${HTTP_BIND:-}:${HTTP_PORT:-3000}:3000"`. See [Ports to open](/get-started/deployment#ports-to-open).
2. **Check LiveKit signaling, if you run voice.** Signaling (port 7880) is now published on `127.0.0.1` only. If browsers connected to `ws://<server>:7880` directly, put a TLS proxy in front of `127.0.0.1:7880` or set `LIVEKIT_HTTP_BIND` in `.env` (with your own keys, never `--dev`). See [Run LiveKit on a server](/channels/voice-setup#run-livekit-on-a-server).
3. **Add the browser container.** The `web-browser` tool now runs Chrome in its own `browser` service, which needs `docker/seccomp-chrome.json` next to your compose file. Follow [Upgrading from an older install](/integrations/web-browser#upgrading-from-an-older-install); re-running `install.sh` fetches the seccomp profile once your compose file refers to it.
4. **Decide on autonomy gating.** `autonomy.gating` now defaults to `band`: the autonomy score, not the contact's tier, decides when Curia asks first. To keep the old tier gates for now, set `gating: tier` under `autonomy:` in `config/local.yaml`. `band` needs the escalation judge (`escalation.judge.enabled: true`, the default), and startup fails without it. See [Autonomy](/core-concepts/autonomy).
5. **Re-save the Nylas key if asked.** Legacy mailbox and Nylas vault keys migrate at boot. If email reports the Nylas key missing afterwards, re-save it in **Settings → Channels → Email**.
6. **Move off `/api/messages`.** The bearer-token message routes were removed. Anything that called them must use console chat instead. See [HTTP channel](/channels/http).

`install.sh` checks what Docker actually published after the update, and warns about Postgres, port 3000, LiveKit signaling and a missing browser service.

## Versioning policy

Curia follows [Semantic Versioning](https://semver.org):

| Change type | Bump | Examples |
|---|---|---|
| New tool, skill, agent, or channel | Minor (`0.X.0`) | Adding web-search, adding Signal channel |
| New capability shipped for the first time | Minor (`0.X.0`) | Autonomy engine, entity context enrichment |
| Completing a partially-shipped feature | Patch (`0.x.Y`) | Context summarization, audit log hardening |
| Bug fix, small improvement | Patch (`0.x.Y`) | Fixing a tool error path |
| Breaking change to public API surface | Minor + changelog note | Renaming a ToolContext field |

**Public API surfaces** (changes called out explicitly even pre-1.0):
- `tool.json` manifest schema
- `ToolHandler` / `ToolContext` / `ToolResult` TypeScript interfaces
- Agent YAML schema (`agents/*.yaml` fields)
- Bus event type definitions (`src/bus/events.ts`)
- Channel adapter interface

**v1.0.0** is reserved for when these surfaces are stable enough to commit to — API stability plus production deployment.
