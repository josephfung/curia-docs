# Diagrams

The SVG diagrams in `assets/` are generated by the Python scripts in this folder. Edit a script, never the SVG: `build.py --check` flags any SVG that doesn't match its script.

| Script | Writes | Used on |
|---|---|---|
| `deployment_architecture.py` | `assets/deployment-architecture.svg` | Get Started → Deployment |
| `multi_agent_architecture.py` | `assets/multi-agent-architecture.svg` | Agents → Multi-agent architecture |
| `architecture_message_flow.py` | `assets/architecture-message-flow.svg` | Core Concepts → Architecture |
| `governance_gates.py` | `assets/governance-gates.svg` | Core Concepts → Layers model |
| `autonomy_bands.py` | `assets/autonomy-bands.svg` | Core Concepts → Autonomy |

`kit.py` holds the shared palette and shapes.

## Commands

You need Python 3.9 or later and nothing else.

```bash
python3 diagrams/build.py                       # rebuild every diagram into assets/
python3 diagrams/build.py governance_gates      # rebuild one
python3 diagrams/build.py --check               # exit 1 if an SVG doesn't match its script
python3 diagrams/build.py --preview /tmp/dia    # square previews, plus PNGs on macOS
```

To check your work, look at a rendered PNG, not the SVG source. On macOS, `--preview` renders each diagram with Quick Look. Quick Look crops to a square, so previews pad the canvas to a square; never copy a preview into `assets/`. Elsewhere, open the SVG in a browser.

## Changing a diagram

1. Change the content in its script. Coordinates are plain numbers, laid out top to bottom in the order the diagram reads.
2. Run `python3 diagrams/build.py <name>`, then look at the preview.
3. Check that the facts still match the page the diagram sits on, and the code behind that page. The page text and the diagram must agree.
4. Update both descriptions: the `DESC` text in the script (the SVG's own accessible description) and the `alt` text where the page embeds the image.
5. Commit the script and the SVG together.

## Adding a diagram

1. Copy the script closest in shape. Give it `OUT` (the file name in `assets/`) and a `build(square=False)` function that returns `Svg(...).render()`.
2. Add its module name to `DIAGRAMS` in `build.py`, and a row to the table above.
3. Embed it the same way the existing pages do:

   ```mdx
   <img
     src="/assets/<name>.svg"
     alt="<what the diagram shows, in full sentences>"
     style={{ width: '100%', height: 'auto', borderRadius: '8px', marginTop: '8px', marginBottom: '8px' }}
   />
   ```

## The visual language

The style follows the "Where your data goes" diagram on [meetcuria.com/governance](https://meetcuria.com/governance), from `src/components/DataFlowDiagram.jsx` in curia-website. Keep these meanings consistent across diagrams:

| Element | Means |
|---|---|
| Teal-filled chip | Curia's own code |
| Sand chip | Open-source software Curia ships, or a plain component |
| Teal-tinted region | The main subject: your server, or the Bullpen |
| Dashed outline, teal | Outside the subject: an outside service, or "add your own" |
| Hollow rounded pill | A person, or a person's device |
| Dark fill | A data store that matters, such as the knowledge graph or `pgdata` |
| Accent (rust) | What happens when something fails, or a warning |
| Small capitals in grey or teal | A group label |
| Numbered teal circle | A step, numbered to match the page's text |

Every diagram draws its own cream background, so it reads the same in light and dark mode. Use static SVG only: no scripts, no interactivity, no Mermaid. Fonts are named, not embedded: Lora for titles and Inter for text, falling back to Georgia and the system sans when a viewer doesn't have them.

Design for about 1,100 px wide. Below roughly 11 px, text becomes hard to read once the page scales the diagram down. If a label doesn't fit, shorten it before shrinking it.
