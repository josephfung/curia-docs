---
title: "Configure Curia's email channel with Nylas integration"
description: "Configure Nylas to give Curia a dedicated email account for sending and receiving."
---

Curia's email channel is powered by [Nylas](https://nylas.com) — a unified API that handles the OAuth and IMAP/SMTP complexity across Gmail, Outlook, and other providers. Once connected, Curia can send emails on your behalf, draft replies for your review, and read your inbox.

## Setup

Email accounts are managed from **Settings → Channels → Email → Email accounts** in the console. You can connect one or many agent-owned mailboxes — each gets its own Nylas grant stored in the vault.

<Steps>
  <Step title="Create a Nylas account">
    Sign up at [app.nylas.com](https://app.nylas.com). The free tier is sufficient for development and small deployments.
  </Step>

  <Step title="Create a Nylas application and seed the API key">
    In the Nylas dashboard, create a new application and choose **Email** as the product. Once created, copy your **API key** and seed it into the vault — this is a one-time, app-level step shared across all email accounts:

    ```bash
    NYLAS_API_KEY=nyk_v0_... pnpm run seed-vault
    ```

    <Tip>
      Only `NYLAS_API_KEY` needs to be seeded manually. Individual account grants are connected through the console in the next step.
    </Tip>
  </Step>

  <Step title="Add an email account from the console">
    In the Curia console, go to **Settings → Channels → Email → Email accounts** and click **Add account**. Give the account a name (e.g., `curia`), then paste the Nylas Grant ID for that mailbox. The console stores the grant in the vault at `channel.email.<name>.nylas_grant_id`.

    To get a grant ID: in the Nylas dashboard, go to **Grants** and add a new grant. This walks you through an OAuth flow to connect a Gmail, Outlook, or other email account to Nylas.

    <Tip>
      Use a dedicated email address for Curia (e.g., `curia@yourdomain.com`) rather than your primary inbox. Curia will read and process all incoming messages on this account.
    </Tip>
  </Step>

  <Step title="Enable the email channel and restart">
    Once at least one account is connected, enable the email channel from **Settings → Channels**. Restart Curia to bring the email adapter online with the new accounts:

    ```bash
    docker compose up -d --force-recreate curia
    ```

    `docker compose logs curia` will show the email adapter initializing. You can add more accounts from the console at any time; each restart picks up the latest set.
  </Step>
</Steps>

<Note>
  You can connect as many email accounts as you need. All accounts share the same app-level `NYLAS_API_KEY`. The `account` parameter on email skills lets agents target a specific account by name; omit it to use Curia's own account.
</Note>

## Email skills

Once the email channel is active, the following skills become available to Curia and any agents you configure:

| Skill | What it does |
|---|---|
| `email-list` | List recent messages in any connected account |
| `email-get` | Fetch the full body of a specific message by ID |
| `email-send` | Compose and send a new email |
| `email-reply` | Reply to an existing thread by message ID |
| `email-draft-save` | Save a draft to a specified account for human review |
| `send-draft` | Send a previously saved draft (CEO-authorized) |
| `email-archive` | Archive a message by ID |

All email skills accept an `account` parameter to target a specific named account. Omit it to use Curia's own account.

## File attachments

Outbound email skills (`email-send`, `email-reply`, and their CEO-inbox counterparts) accept an optional list of attachments. Files are referenced by `file://` URLs backed by Curia's temp-file store rather than passed inline, with a cap of **20 MB total across at most 10 attachments** per message. Anything an agent has written to the temp-file store can be attached; the [`drive-download-file`](/skills/built-in-skills#email) skill bridges Google Drive by downloading a file (including Google-native exports) into that store and returning a `file://` URL ready to attach. No extra configuration is needed beyond a working Nylas grant — attachments ride the same Send API as the message body.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Email channel not activating">
    The `nylas_api_key` must be in the vault and at least one email account must be configured in Settings → Channels → Email → Email accounts. If the API key is missing, the channel disables itself at startup:

    ```
    NYLAS_API_KEY not set — email channel disabled
    ```

    Confirm the API key is seeded with `pnpm run seed-vault`, then verify accounts are configured in the console. Recreate the container after any change.
  </Accordion>

  <Accordion title="Messages not appearing">
    Curia polls the Nylas Messages API every 30 seconds by default. If messages are slow to appear, confirm the email account's OAuth grant is active in the Nylas dashboard and that the grant ID entered in Settings → Channels → Email → Email accounts matches the one shown in the Nylas Grants view.

    You can also adjust the polling interval (non-secret config in `.env`):

    ```env
    NYLAS_POLL_INTERVAL_MS=15000
    ```
  </Accordion>

  <Accordion title="Outbound emails going to drafts unexpectedly">
    Outbound sends are governed by the [autonomy engine](/core-concepts/autonomy). If your autonomy score is below 70, `email-send` and `email-reply` are blocked and drafts are saved instead. Ask Curia its current score ("What is your autonomy score?") and raise it if needed.
  </Accordion>
</AccordionGroup>
