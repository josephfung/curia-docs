Curia ships with a small team of specialized agents. The **Coordinator** is the central router — every inbound message goes to it first. It handles most tasks directly and delegates to specialist agents when their expertise is needed.

## Coordinator

The Coordinator is Curia's primary agent. It receives every inbound message, maintains the unified persona, and decides whether to handle a task itself or delegate to a specialist.

| Field | Value |
|---|---|
| **Role** | coordinator |
| **Model** | Standard tier (Claude Sonnet by default) |
| **Pinned skills** | 60+ tools across the email, memory, scheduling, tasks, web, autonomy, and Google Workspace skills, and more |
| **Discovery** | Enabled — can find and invoke skills not in its pinned list |
| **Task management** | Enabled (pins the `tasks` skill) — owns and advances the task backlog |

**What it handles directly:**
- Conversational messages and questions
- Email reading, sending, replying, and drafting
- Scheduling recurring and one-shot tasks
- Tracking deferred work in the [task backlog](/core-concepts/scheduling#tasks-and-the-backlog) — "remind me to…", "what's open?", "mark X done"
- Knowledge graph queries and memory storage
- Autonomy score management
- Web research (search, fetch, browse)
- Handling unknown senders in read-only mode (auto-created at the `unknown` tier)

**What it delegates to specialists:**
- Calendar operations and scheduling intelligence → Calendar Specialist
- Contact briefings, deduplication, and relationship intelligence → Contact Specialist
- Multi-source web research → Research Analyst
- CEO inbox queries, triage, and rule management → CEO Inbox
- First-conversation onboarding and "help me set up X" requests → Setup Wizard
- "What happened / why?" forensics about Curia's own behavior → Diagnostics (when enabled)

**Key behaviors:**
- Resolves possessive pronouns ("my calendar", "your schedule") to explicit entity identities before delegating to any specialist
- Adapts its communication style based on who it's talking to — candid with the CEO, professional and opaque with external contacts
- Never exposes internal system details, tool names, or agent architecture to non-CEO users
- Enforces authorization decisions from the dispatch layer (unknown-tier contacts, blocked senders, permission denials)
- Respects trust score thresholds before taking action on external requests
- Recognizes when it was CC'd (vs. directly addressed) on email and adjusts behavior — reads the thread for context, infers what's expected, and replies via the correct account

## Calendar Specialist

A specialist agent that owns the full calendar domain.

| Field | Value |
|---|---|
| **Role** | specialist |
| **Model** | Standard tier (Claude Sonnet by default) — scheduling and RSVP judgment |
| **Tools** | calendar-* (incl. holds and invite RSVPs), contact-lookup, entity-context, date-resolve, memory-query, memory-store, bullpen |
| **Discovery** | Disabled |

**What it handles:**
- Scheduling intelligence — finds free time, resolves conflicts, and applies the CEO's scheduling rules, loaded deterministically from config-store at the start of each task so preferences (no-meeting windows, default durations) are reliably enforced (`free`-status events are treated as available)
- Free/busy queries across multiple calendars and participants
- Event CRUD (create, update, delete) with timezone-aware slot finding
- Tentative holds — places `HOLD (TBC)` events on offered slots so they are not double-offered while a negotiation is in flight, auto-releases them when a real event is booked, and sweeps expired holds daily
- Scheduling consults — answers `CONSULT REQUEST`s from the CEO Inbox (and other agents) over a Bullpen thread: resolves free slots, places holds, and replies with timezone-labelled options before a scheduling email is drafted
- Calendar invite RSVPs — evaluates formal invites (relationship tier, sender kind, conflicts) and sends accept / decline / tentative responses via Nylas, releasing any matching hold
- Scheduling-related message drafting — meeting requests, reschedules, cancellations (the Calendar Specialist has no email skills; it returns the drafted text to the Coordinator to send)

The Coordinator delegates scheduling intent in natural language ("schedule a 30-minute call with Sarah next week"). The Calendar Specialist resolves entities, loads the CEO's scheduling rules from config-store, finds available time, creates the event, and drafts any outgoing message — returning the result to the Coordinator, which sends it.

## Contact Specialist

A specialist agent that owns the full contact domain.

| Field | Value |
|---|---|
| **Role** | specialist |
| **Model** | Fast tier (Claude Haiku by default) |
| **Tools** | contact-*, scan-grant-recommendations, approve-grant-recommendation, decline-grant-recommendation, query-relationships, delete-relationship, calendar-list-events (read-only), scheduler-report, context-bridge-release, context-bridge-clear, entity-context, memory-query, memory-store |
| **Discovery** | Disabled |

**What it handles:**
- Contact briefings — assembles enriched context (facts, relationships, interaction history) for a person or organization
- Contact CRUD and identity management
- Deduplication — runs a weekly background scan and surfaces merge candidates for CEO review
- Entity resolution for people and organizations

The Coordinator delegates contact intelligence via a natural-language pattern ("brief me on Sarah Chen before the call"). The Contact Specialist returns enriched context and resolved contact IDs in a structured block, which the Coordinator uses to inform its response or subsequent actions.

## Research Analyst

A specialist agent for conducting web research and providing analysis.

| Field | Value |
|---|---|
| **Role** | specialist |
| **Model** | Fast tier (Claude Haiku by default) |
| **Tools** | web-search, web-fetch, request-clarification, scheduler-create, scheduler-list, scheduler-cancel, memory-query, memory-store, contact-update |
| **Discovery** | Disabled |

**Research workflow:**
1. Uses web-search (Tavily) with multiple queries to cover different angles
2. Follows up on important sources with web-fetch for full content
3. Synthesizes findings into clear, concise summaries for an executive audience
4. Highlights key takeaways and concerns with source attribution
5. Persists important findings about known entities to the knowledge graph, so research about contacts and organizations builds over time

The Coordinator delegates to the Research Analyst when a request requires multi-source web research rather than a simple lookup.

## CEO Inbox

A specialist agent that manages the CEO's personal email inbox. It runs on a 15-minute schedule and can also be delegated inbox queries or rule management tasks by the Coordinator.

| Field | Value |
|---|---|
| **Role** | specialist |
| **Model** | Standard tier (Claude Sonnet by default) |
| **Tools** | ceo-inbox-* (incl. `ceo-inbox-draft-compose`), task-* (via task management), contact-register, contact-update, bullpen, entity-context, memory-query, memory-store, config-store, executive-profile-get, file-parse, date-resolve, scheduler-report, context-bridge-release, context-bridge-clear |
| **Discovery** | Disabled |
| **Task management** | Enabled (pins the `tasks` skill) |
| **Schedule** | Every 15 minutes |

**What it handles:**
- Autonomous inbox triage — reads unread messages and classifies each as URGENT, ACTIONABLE, NEEDS DRAFT, LEAVE FOR CEO, or NOISE
- Draft reply creation — writes reply-all drafts in the CEO's voice using the stored executive profile; the CEO reviews and sends from Gmail
- Cold-outreach drafts — composes new (non-reply) drafts into the CEO's Gmail Drafts via `ceo-inbox-draft-compose`
- Escalation — sends a Signal alert and opens a Bullpen thread for URGENT items; opens a Bullpen thread mentioning the appropriate specialist for ACTIONABLE items
- Standing rules and decision tagging — maintains a configurable set of per-sender instructions and auto-labels via `config-store`
- Scheduling replies via calendar consult — for meeting and scheduling emails it consults the Calendar Specialist over a Bullpen thread (which checks conflicts and places tentative holds) and parks the draft pending the reply, rather than guessing times blind; a `consult-timeout` safety wake falls back to a blind draft or escalation if no reply arrives
- Invite triage — formal calendar invites are linked to calendar events and routed to the Calendar Specialist, which evaluates the invite and sends the RSVP, releasing any matching hold
- Inbox queries — searches, reads, and labels messages on demand when delegated by the Coordinator

The CEO Inbox agent runs directly against the CEO's personal email account via Nylas. It never replies directly to senders — all outbound replies go through draft creation for CEO review.

**Tasks keep the loop closed.** When a reply depends on something not yet available (a document the CEO must provide, a fact to look up), the agent creates a tracked follow-up [task](/core-concepts/scheduling#tasks-and-the-backlog) rather than sending a bare "the CEO will follow up" — it resolves the dependency first where it can, and resumes drafting when the task wakes. On a backed-up inbox it drains messages in fixed-size, self-continuing batches (keyed on read/archive status) until the inbox is clear, so the time spent per run stays bounded regardless of backlog.

**Urgent alerts route through the coordinator.** When the CEO Inbox classifies a message as URGENT, it does not call `signal-send` directly — it opens a Bullpen thread mentioning the coordinator and asks for an outbound alert. The coordinator's send is what hits Signal, which means the alert participates in the same delegation-aware reply correlation as any other coordinator-initiated message. If the CEO replies to the alert, the coordinator routes the reply back to the inbox agent via the normal delegation path.

## Setup Wizard

A specialist agent that owns the first-conversation experience after a new install and stays available for "help me set up X" requests later.

| Field | Value |
|---|---|
| **Role** | specialist |
| **Model** | Standard tier (Claude Sonnet by default) |
| **Tools** | setup-status, setup-defer, behavioral-preferences-update, scheduler-create, scheduler-list, scheduler-cancel, tool-registry, memory-store, executive-profile-update, system-secret-capture-request |
| **Discovery** | Disabled |
| **inject_specialists** | False |

**When it runs:**
- Auto-triggered on the first chat message after the form wizard at `/setup` completes. The chat view sends a one-shot kickoff message that the Coordinator routes here.
- On demand when the principal asks "help me set up Nylas / Signal / Tavily / OpenAI" or similar. For channel credentials (email, Signal) it hands off to the console (Settings → Channels) and confirms via `setup-status`; for one-key secrets (Tavily, OpenAI) it mints a one-time secure capture link via `system-secret-capture-request` so the key goes straight to the vault without the agent ever seeing it.
- On "what can you do?" — returns a plain-language capability summary grouped by category.

**First-conversation flow:**
1. Greet, then ask what takes up most of the principal's time (email, scheduling, research, news).
2. Map the answer to concrete next steps (email-heavy → Nylas setup; research → web search is already wired) and append the preference to `OfficeIdentity.behavioralPreferences` via `behavioral-preferences-update`. Then ask about working hours and timezone.
3. Acknowledge the hours and ask whether a regular debrief would be useful — daily summary or weekly digest.
4. If yes, schedule the debrief via `scheduler-create`. Close with a brief summary of what got set up and what's next.

The Setup Wizard never addresses the principal directly — like every other specialist, its output is paraphrased and relayed by the Coordinator. It has no persistent per-conversation state; each invocation is fresh, with the "this is a first conversation" signal coming from the kickoff message text itself rather than a stored flag.

## Meeting Debrief

A proactive specialist agent that scans the CEO's calendar for recently-ended external meetings, prompts for takeaways, and executes whatever follow-up actions the CEO's notes imply.

| Field | Value |
|---|---|
| **Role** | specialist |
| **Model** | Standard tier (Claude Sonnet by default) |
| **Tools** | calendar-list-events, calendar-create-event, calendar-check-conflicts, contact-lookup, email-draft-save, task-*, bullpen, memory-query, memory-store, config-store, entity-context, date-resolve, context-bridge-clear |
| **Discovery** | Disabled |
| **Schedule** | Every 5 minutes |

**What it handles:**
- **Detection** — scans calendar events ending in the recent past, classifies attendees as internal vs external, and uses LLM judgment to decide which meetings warrant a debrief prompt (`YES`, `NO`, `DEFER`)
- **Prompting** — opens a Bullpen thread asking the coordinator to send a brief conversational prompt on the CEO's preferred channel (Signal by default): *"You just wrapped up with Sarah Chen and David Park from Meridian. Any takeaways or follow-ups?"*
- **Follow-up execution** — when the CEO replies with notes, the agent uses its full skill set to draft emails, find conflict-free meeting slots, store commitments, and post Bullpen threads to other specialists (e.g. research-analyst) for cross-cutting work
- **Reminders** — nudges the CEO on the same thread if a prompt goes unanswered after a configurable delay (default: 2 hours)
- **Preference learning** — when the CEO says *"don't debrief me on meetings with X"*, the rule is stored as a KG fact and respected on future scans

**State is tracked as tasks.** Each pending debrief is a [task](/core-concepts/scheduling#tasks-and-the-backlog) (tagged `debrief-pending`), and the reminder is just that task's wake-up; follow-up actions become child tasks owned by Curia, you, or an external party. You can ask "what debriefs are outstanding?" through the coordinator at any time.

**Bullpen-through-coordinator pattern.** The Meeting Debrief agent has no outbound communication skills pinned. All proactive prompts and follow-up sends route through the coordinator via Bullpen, which keeps the unified persona intact and lets reply correlation work the same way as any other coordinator-initiated outbound.

Tunable via the `debrief` block in `config/default.yaml` — channel, reminder delay, scan window, and context-bridge TTL for replies.

## Diagnostics

An opt-in, read-only investigator for the principal. When something about Curia's own behavior looks off — a duplicate notification, an email that never got processed, a blocked message, a scheduler double-fire — you can ask it *what happened* and *why*. Given an ID, a time window, or a symptom, it reads the audit log and operational state, follows the causal chain, and returns an ordered event narrative, a grounded root-cause hypothesis (citing the audit events it relied on), and a suggested mitigation.

| Field | Value |
|---|---|
| **Role** | specialist |
| **Model** | Powerful tier (Claude Opus by default) |
| **Tools** | audit-query, audit-trace, ops-lookup, date-resolve, request-clarification |
| **Discovery** | Disabled |
| **Enabled by default** | No — operator must enable it |

**Read-only by construction.** Every tool it holds is read-only; it investigates but never acts. It has no ability to send, draft, write state, or contact anyone. `ops-lookup` reads operational tables (`scheduled_jobs`, `action_log`, `outbound_context`, `working_memory`, `messages`); `audit-query` and `audit-trace` read the audit log.

**Principal-only.** Its findings are Curia's own internal state, so it reports only to the principal and declines diagnostics requested on behalf of — or for delivery to — anyone else. It grounds every claim in cited audit events rather than guessing, and treats expired ephemeral state (e.g. `outbound_context`, `working_memory`) as unavailable instead of confabulating.

**Off by default.** The Diagnostics agent and its `audit-query` / `audit-trace` / `ops-lookup` tools are excluded from the default registry — a fresh install does not enable them. Turn the agent on (and its tools) from **Settings → Skills** when you want it. Once enabled, the Coordinator delegates to it like any other specialist and relays its findings.

## How delegation works

When the Coordinator receives a task that requires specialist expertise, it uses the `delegate` tool to hand the task to the appropriate agent. The specialist works independently, using only its pinned skills, and returns its findings to the Coordinator. The Coordinator synthesizes the specialist's response into its own voice — the user never sees that multiple agents were involved.

On synchronous channels (CLI, Signal, HTTP), the Coordinator sends a brief acknowledgment before delegating ("This will take a few minutes — I'll reply when it's ready"). On asynchronous channels (email), delegation happens silently.
