Curia maintains a persistent knowledge graph of the people, organizations, projects, decisions, and facts that matter to your work. This graph grows automatically from your emails, conversations, and explicit corrections — and it persists across restarts, retains source attribution, and ages facts gracefully over time. The knowledge graph browser is a visual interface for exploring everything Curia has learned.

## Accessing the web app

Open [http://localhost:3000](http://localhost:3000) in your browser. You'll be prompted for your `WEB_APP_BOOTSTRAP_SECRET` — the value you set in `.env` when you configured Curia.

```env
WEB_APP_BOOTSTRAP_SECRET=replace-with-a-long-random-secret
```

After authenticating, the knowledge graph browser is available at `/kg`.

<Info>
  If `WEB_APP_BOOTSTRAP_SECRET` is not set in your environment, the knowledge graph API is intentionally disabled. Set the variable and restart Curia to enable it.
</Info>

## What the knowledge graph contains

The graph stores four types of things:

## Browsing nodes

The main graph view shows nodes and their relationships. Use the search bar to find specific people or topics:

- **Search by name**: Type a name or partial name to find matching nodes
- **Filter by type**: Filter to `person`, `organization`, `project`, `event`, `decision`, or `concept`
- **Select a node**: Click any node to center the view on it and expand its neighbors

When you select a node, Curia loads its neighborhood — the nodes directly connected to it, up to 3 hops deep. The `depth` parameter in the URL controls traversal depth if you want to explore further.

## Entity memory — facts with confidence scores

Click a `person` or `organization` node to open its entity memory panel. This shows all facts Curia has recorded about the entity:

| Column | What it means |
|---|---|
| **Fact** | The recorded information (e.g., "CFO at Acme Corp") |
| **Confidence** | 0.0–1.0 scale — how certain Curia is that this fact is still true |
| **Source** | Which agent, channel, or conversation recorded it |
| **Decay class** | How quickly the fact's confidence decays over time |

### Decay classes

Not all facts age the same way. Curia assigns each fact a decay class based on how stable the underlying information tends to be:

| Decay class | Half-life | Examples |
|---|---|---|
| `permanent` | Never decays | Legal name, date of birth, birth city |
| `slow_decay` | ~180 days | Employer, job title, city of residence |
| `fast_decay` | ~21 days | Coffee preference, current project focus, travel schedule |

A fact's confidence score decreases over time based on its decay class. Stale information loses confidence rather than being trusted indefinitely. When Curia encounters new evidence that confirms a fact, `last_confirmed_at` updates and confidence rises again.

## Semantic search

The search bar supports natural language queries beyond exact name matches. Because node descriptions and facts are embedded using OpenAI's `text-embedding-3-small` model, you can ask:

```
find everything related to fundraising
```

```
show me people connected to the Q3 board meeting
```

```
investors who attended the Series A close
```

Semantic search matches nodes whose embeddings are similar to your query — even when the exact words don't appear in any node labels.

<Note>
  Semantic search requires `OPENAI_API_KEY` to be set. Without it, the graph browser falls back to exact-match label and property search.
</Note>

## Relationship types

Edges in the knowledge graph represent typed relationships between nodes. Curia infers these from email threads, calendar events, and conversation context:

| Relationship type | Meaning |
|---|---|
| `works_on` | A person is working on a project |
| `decided` | A person or group made a decision |
| `attended` | A person attended an event |
| `relates_to` | A general association between two nodes |
| `reports_to` | Organizational hierarchy |
| `invested_in` | An organization or person invested in another |

You can query relationships conversationally as well — Curia uses the `query-relationships` skill to look up all stored relationships for any entity by name.

## How Curia populates the graph

The knowledge graph grows automatically from several sources:

- **Emails**: Participant extraction from From/To/CC headers auto-creates contact nodes and infers organizational relationships
- **Conversation context**: When you mention people, projects, or decisions in conversation, Curia extracts and stores structured facts
- **Explicit corrections**: You can tell Curia new facts directly — "Mark Chen is now our CFO" — and it updates the graph with proper source attribution
- **Calendar events**: Attendees and events create and reinforce relationship nodes

### Deduplication and contradiction handling

Before writing any new fact, Curia checks for existing nodes with similar labels (using embedding cosine similarity). If a near-duplicate exists, it merges properties rather than creating a new node. If the new fact contradicts an existing one (e.g., a different employer for the same person), Curia compares confidence scores: the higher-confidence fact wins, and the lower-confidence fact is archived with its previous value preserved for audit.

## Correcting the graph

The graph isn't always right. When Curia records something incorrect, tell it directly:

```
> That relationship is wrong — Mark Chen doesn't report to Sarah. Remove it.
```

```
> Alice isn't at Acme Corp anymore. She joined Beacon Capital last month.
```

Curia uses `delete-relationship` to remove incorrect edges and updates entity facts when you provide corrections. Every correction is audit-logged with your confirmation as the source.

When Curia detects a potential duplicate contact — two nodes that appear to represent the same person — it surfaces the conflict and walks you through a merge decision before making any changes. It never auto-merges without your confirmation.
