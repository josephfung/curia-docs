## What this is for

Two capabilities this page covers:

- **Memory (works out of the box).** Curia's memory, the knowledge graph of people, organisations and facts, runs on an embedding model bundled in the Curia image. It needs no key and sends nothing off your server. The setup assistant, working hours from setup and the sensitivity classifier that flags confidential content all depend on it. What's left for you is to turn on the tools that build memory from conversations, and optionally to [swap the model](/integrations/embeddings-endpoint) for a larger one or OpenAI.
- **Web search (works out of the box).** Curia searches the web through [Tavily](https://tavily.com) for research and news. With no key, searches are free but capped at a few dozen an hour. A free Tavily key raises the limit.

## What you'll need

- **Nothing, for memory with the bundled model.**
- **Optionally, another embedding model:** your own OpenAI-compatible embedding server, such as [Ollama](https://ollama.com) running an embedding model, or an [OpenAI](https://platform.openai.com) API key with billing set up. Worth it mainly for languages other than English, since the bundled model is English-only.
- **Optionally, a Tavily account,** if you want more searches than the keyless limit allows.
- **Shell access to the Curia host,** only if you swap the embedding model. There's no console field for it yet.

**Time:** about 5 minutes, or 15 if you swap the embedding model.

**Cost** (checked 2026-11-01):

- The bundled embedding model: no fee. It runs inside Curia.
- OpenAI `text-embedding-3-small`, if you choose it: $0.02 per million tokens.
- Your own embedding server: no fee, but it runs on your hardware.
- Tavily: free without a key (capped per hour). A free key adds 1,000 credits a month, no card needed.

<Note>
  The bundled embedding model is newer than the latest release (v0.45.0, 2026-11-17), and reaches the default `latest` image with a later release. On v0.45.0, memory needs an embedding source: your own [embedding server](/integrations/embeddings-endpoint), or an OpenAI key stored in the vault as `openai_api_key`:

  ```bash
  docker compose run --rm -e SEED_VAULT_ONLY=openai_api_key -e OPENAI_API_KEY=sk-... \
    curia ./node_modules/.bin/tsx scripts/seed-vault.ts
  docker compose restart curia
  ```

  After you upgrade, an install on that OpenAI key keeps OpenAI through a deprecated default; [OpenAI embeddings](/integrations/openai-embeddings#older-installs-the-implicit-openai-default) explains how to move off it.
</Note>

## Steps

<Steps>
  <Step title="Optional: choose a different embedding model">
    Skip this to keep the bundled model. To use another one:

    - **Your own server:** set `EMBEDDING_BASE_URL` and `EMBEDDING_MODEL` in `.env`, add a key if the server needs one, and recreate the container. The steps are on [Embedding models](/integrations/embeddings-endpoint).
    - **OpenAI:** set OpenAI's address and model in `.env` and its key in the vault. The steps are on [OpenAI embeddings](/integrations/openai-embeddings).

    Choose before Curia stores much in memory. Switching models later means re-embedding the whole graph once.
  </Step>

  <Step title="Turn on fact extraction">
    Two background tools build memory from conversations, and they stay off on a new install even after you add embeddings. In the console, go to **Tools**, then install and enable `extract-facts` and `extract-relationships`.
  </Step>

  <Step title="Restart Curia">
    Curia picks up the newly enabled tools, and any embedding change, when it starts. Restart from the console's **Settings → System → About** page, or run:

    ```bash
    docker compose restart curia
    ```

    If you changed `.env` for your own embedding server, run `docker compose up -d curia` instead, so the container picks up the new values.
  </Step>

  <Step title="Optional: add a Tavily key for more searches">
    Web search is already on. Add a key only if you expect more than a few dozen searches an hour, or if Curia reports that search is temporarily limited.

    Sign up at [tavily.com](https://tavily.com) and copy your API key (it starts with `tvly-`). Then either:

    - In the console, go to **Settings → Tools → web-search → Optional secrets** and save the key in `tavily_api_key`.
    - Or ask Curia in chat to "add my Tavily key". The setup assistant sends a one-time secure link that saves the key to the same place.

    The key is used from the next search. No restart needed.
  </Step>
</Steps>

## Check it works

1. Call `/api/health`: `checks.knowledge_graph` should read `"ok"`. In the logs (`docker compose logs curia`), look for `Entity memory initialized with knowledge graph`; its `embeddingSource` is `bundled` unless you swapped the model. If the check reads `"fail"`, `details.knowledge_graph` names the reason, and a log line ending in `knowledge graph unavailable` says what to do. See [Embedding models](/integrations/embeddings-endpoint#see-which-model-is-active).
2. In the console chat, tell Curia a harmless fact, such as the name of a colleague and their role, then later ask about it.
3. For web search, ask something only a live search can answer, such as today's news on a topic. If you added a Tavily key, Curia's daily health check logs `Health canary result` with `"canary":"tavily"` and `"status":"ok"` once the key works. Without a key, it reports `skipped`.

## What your principal will notice

- **With memory on,** Curia remembers people, organisations and decisions across conversations and channels. It builds up gradually over weeks rather than all at once.
- **Web search,** on by default, lets Curia answer questions about current events and research topics with up-to-date sources. Without a Tavily key, heavy use can hit the hourly cap. Curia then says search is temporarily limited and when it should work again.
- **Without memory,** Curia still answers, but doesn't build up what it knows about people and facts from one conversation to the next.
