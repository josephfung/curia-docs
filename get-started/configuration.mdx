Curia uses two configuration layers: a `config/default.yaml` file that ships with the repository and defines all defaults, and a `config/local.yaml` file that you create to override specific values for your deployment. Secrets — API keys, credentials, and tokens — live in an [encrypted vault](/get-started/secrets-vault), not in `.env` and not in YAML files. Only the four values needed to reach and unlock that vault, plus non-secret deployment config, stay in `.env`.

<Note>
  First-time setup configures everything for you. `pnpm run setup` writes the four bootstrap values to `.env`, prompts for your Anthropic API key, and seeds it (along with the generated API token and login secret) into the encrypted vault after migrations. The in-app setup wizard then captures your identity, operational details, and the assistant's voice and posture. This page covers everything you might want to change later — channels, MCP skill credentials, custom LLM routing, and adding secrets to the vault.
</Note>

<Warning>
  Most configuration changes take effect on restart. After editing `.env` or any YAML file, recreate the Curia container to apply changes: `docker compose up -d --force-recreate curia`. Adding or updating a vault secret with `VAR=value pnpm run seed-vault` does not require editing `.env`, but recreate the container afterward so running skills pick up the change.
</Warning>

## How configuration works

When Curia starts, it merges `config/local.yaml` on top of `config/default.yaml`. Any key you set in `local.yaml` overrides its default. Keys you omit stay at their default values. You never need to copy the entire `default.yaml` — only override what you need.

```yaml
# config/local.yaml — only include what you want to change
dispatch:
  rate_limit:
    max_per_sender: 30

intentDrift:
  minConfidenceToPause: medium
```

## Environment variables

`.env` holds only two kinds of values: the four bootstrap secrets needed to reach and unlock the vault, and non-secret deployment config. Every other credential — LLM keys, Nylas, Signal, Tavily, the HTTP API token, the login secret — lives in the [encrypted vault](/get-started/secrets-vault) and is seeded with `pnpm run seed-vault`.

### What stays in `.env`

| Variable | Required | Description |
|---|---|---|
| `DB_USER` | Yes | PostgreSQL user. |
| `DB_PASSWORD` | Yes | PostgreSQL password. |
| `DATABASE_URL` | Yes | Postgres connection string. Constructed from `DB_USER`, `DB_PASSWORD`, and `POSTGRES_PORT` by `pnpm run setup`. |
| `SECRET_ENCRYPTION_KEY` | Yes | Base64-encoded 32-byte AES-256 master key that encrypts the vault. Generate with `openssl rand -base64 32`; `pnpm run setup` fills it in. **Back this up — losing it makes the vault unrecoverable.** |
| `TIMEZONE` | No | IANA timezone (e.g. `America/Toronto`). Used to resolve relative dates in agent prompts. |
| `HTTP_PORT` / `POSTGRES_PORT` | No | Host ports for the app and Postgres. Defaults `3000` / `5432`. |
| `NYLAS_POLL_INTERVAL_MS` | No | Email poll interval in ms (default `30000`). Non-secret. |
| `NODE_EXTRA_CA_CERTS` | No | Path to a CA bundle (macOS TLS workaround). |

```env
DB_USER=curia
DB_PASSWORD=<generated-by-setup>
DATABASE_URL=postgres://curia:<password>@localhost:5432/curia
SECRET_ENCRYPTION_KEY=<openssl rand -base64 32>
TIMEZONE=America/Toronto
```

### What goes in the vault

These secrets are seeded into the encrypted vault, never written to `.env`. Set each transiently on the command line and run the seed script — the value is read from the process environment, encrypted, and stored:

```bash
ANTHROPIC_API_KEY=sk-ant-... pnpm run seed-vault
```

The script maps each environment variable to its canonical vault key:

<AccordionGroup>
  <Accordion title="LLM providers">
    | Env var (transient) | Vault key | Notes |
    |---|---|---|
    | `ANTHROPIC_API_KEY` | `anthropic_api_key` | Powers all agents. Seeded automatically on first setup. |
    | `OPENAI_API_KEY` | `openai_api_key` | Knowledge graph embeddings (`text-embedding-3-small`) and semantic search. |
    | `OPENROUTER_API_KEY` | `openrouter_api_key` | Optional. Enables multi-model routing via [OpenRouter](https://openrouter.ai). |

    Ollama requires no API key — configure the endpoint in your agent YAML instead.
  </Accordion>

  <Accordion title="Authentication and access">
    | Env var (transient) | Vault key | Notes |
    |---|---|---|
    | `API_TOKEN` | `api_token` | Bearer token for all HTTP API requests. Generated and seeded by `pnpm run setup`. |
    | `WEB_APP_BOOTSTRAP_SECRET` | `web_app_bootstrap_secret` | Secret for logging in to the console. Generated and shown once by `pnpm run setup`. |
  </Accordion>

  <Accordion title="Email (Nylas)">
    Only the app-level API key needs to be seeded into the vault. Individual email account grants are managed from the console (Settings → Channels → Email → Email accounts) — they are stored automatically in the vault when you connect an account.

    | Env var (transient) | Vault key | Notes |
    |---|---|---|
    | `NYLAS_API_KEY` | `nylas_api_key` | Application API key from the Nylas dashboard. Required for the email channel to start. |

    ```bash
    NYLAS_API_KEY=nyk_v0_... pnpm run seed-vault
    ```

    See [Email setup](/channels/email-setup) for the full walkthrough.
  </Accordion>

  <Accordion title="Signal">
    | Env var (transient) | Vault key | Notes |
    |---|---|---|
    | `SIGNAL_PHONE_NUMBER` | `signal_phone_number` | Your E.164 phone number (e.g. `+12223334444`). Must match the number registered via `signal-cli register` + `verify`. |

    Do not set `SIGNAL_SOCKET_PATH` — the deployment layer manages this automatically.
  </Accordion>

  <Accordion title="Web search">
    | Env var (transient) | Vault key | Notes |
    |---|---|---|
    | `TAVILY_API_KEY` | `tavily_api_key` | API key from [tavily.com](https://tavily.com). Required before the `web-search` skill can be enabled. |

    The `web-search` skill declares `tavily_api_key` in its `install.requires_secrets`, so the registry will not let you enable it until the key is in the vault. See [Managing skills, agents, and channels](/core-concepts/registry).
  </Accordion>
</AccordionGroup>
