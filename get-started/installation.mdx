---
title: "Install Curia"
description: "Get Curia running with a single command, then add the channels and capabilities you need."
---

Getting Curia running takes one command and about five minutes. `pnpm run setup` generates your secrets, starts the database and app in Docker, and runs migrations — the only thing you provide is an Anthropic API key. Once it's running, you finish configuration inside the app and add optional capabilities (email, search, Signal) whenever you need them.

## Prerequisites

Before you start, install the following:

- **Node.js 22 or later** — verify with `node --version`
- **Docker and Docker Compose** — Postgres and the app both run in Docker; install [Docker Desktop](https://www.docker.com/products/docker-desktop/) or the standalone CLI
- **pnpm** — install with `npm install -g pnpm`

<Note>
  Setup also uses `openssl` to generate secrets. It ships by default on macOS and most Linux distributions, so you likely already have it.
</Note>

## Quick start

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/josephfung/curia.git
    cd curia
    ```
  </Step>

  <Step title="Run setup">
    ```bash
    pnpm run setup
    ```

    This single command does everything needed to get Curia running:

    - Checks that Docker, Node, and pnpm are available
    - Generates cryptographically random secrets (database password, API token, web app bootstrap secret) and writes them to `.env`
    - Prompts you for an Anthropic API key — get one at [console.anthropic.com](https://console.anthropic.com)
    - Starts Postgres, waits for it to be healthy, and runs database migrations
    - Starts the full Curia stack in Docker

    The Anthropic key is the only value you supply. Everything else is generated for you.
  </Step>

  <Step title="Save your bootstrap secret">
    When setup finishes, it prints a summary box with your login URL and a **bootstrap secret**:

    ```
    ╔══════════════════════════════════════════════════════════════════════╗
    ║   Curia is running.                                                    ║
    ║   Open:    http://localhost:3000                                       ║
    ║   Bootstrap secret (save this to a password manager):                  ║
    ║   a1b2c3d4...                                                          ║
    ╚══════════════════════════════════════════════════════════════════════╝
    ```

    Save the bootstrap secret to a password manager now. You'll use it to log in, and it won't be shown again.
  </Step>

  <Step title="Log in and finish in the app">
    Open [http://localhost:3000](http://localhost:3000) and enter your bootstrap secret to create your account.

    Once you're in, the **setup wizard** walks you through the rest conversationally — naming your instance, setting its persona and voice, and configuring the CEO profile it operates on behalf of. This takes a few minutes and makes every subsequent interaction more useful.

    <Note>
      Checkpoint: Curia is running on Anthropic and Postgres. Agents are live and the web app is working. Add email, semantic search, or Signal below whenever you need them.
    </Note>
  </Step>
</Steps>

<Accordion title="Running setup again">
  If `.env` already exists, `pnpm run setup` won't overwrite it. Instead it offers a short menu:

  - **Start the stack** — bring the containers back up (`docker compose up -d`)
  - **Resume setup** — re-run database migrations and startup against your existing `.env`, useful if a previous run didn't finish
  - **Full reset** — regenerate all secrets. This invalidates active sessions and requires typing `yes` to confirm

  Your secrets are never silently regenerated, because rotating them would invalidate live sessions.
</Accordion>

## Full setup

The quick start gives you a running instance on Anthropic and Postgres. The capabilities below are optional and independent — add them in any order, only when you need them.

Each one follows the same pattern: add the relevant variables to `.env`, then recreate the Curia container to pick up the change:

```bash
docker compose up -d --force-recreate curia
```

### Email (Nylas)

Curia uses [Nylas](https://nylas.com) as its email layer — a unified API that handles IMAP and SMTP complexity and provides a consistent interface across Gmail, Outlook, and other providers.

<Steps>
  <Step title="Create a Nylas account">
    Sign up at [app.nylas.com](https://app.nylas.com). The free tier is sufficient for development.
  </Step>

  <Step title="Create an application">
    In the Nylas dashboard, create a new application and choose **Email** as the product. Once created, copy your **API key** — this is your `NYLAS_API_KEY`.
  </Step>

  <Step title="Connect an email account">
    In your application, go to **Grants** and add a new grant. This connects an email account (Gmail, Outlook, and others) to your Nylas application via OAuth. Use the address you want Curia to read and send from.

    After completing the OAuth flow, copy the **Grant ID** that appears in your dashboard — this is your `NYLAS_GRANT_ID`.

    <Warning>
      Use a dedicated email account rather than your primary inbox for development. Curia reads and processes all incoming messages.
    </Warning>
  </Step>

  <Step title="Set the Nylas environment variables">
    Add these three variables to your `.env`. All three must be present for the email channel to activate:

    ```env
    NYLAS_API_KEY=nyk_v0_...
    NYLAS_GRANT_ID=<grant-id-from-dashboard>
    NYLAS_SELF_EMAIL=curia@yourdomain.com
    ```

    `NYLAS_SELF_EMAIL` is the address Curia reads and sends from — it filters self-sent messages and signs outbound emails.
  </Step>

  <Step title="Apply the change">
    ```bash
    docker compose up -d --force-recreate curia
    ```

    The email channel activates automatically when all three Nylas variables are present.
  </Step>
</Steps>

### Semantic search and entity memory (OpenAI)

OpenAI's `text-embedding-3-small` model powers entity memory and semantic search in the knowledge graph. Without it, knowledge graph lookups are exact-match only.

Get an API key from [platform.openai.com](https://platform.openai.com) and add it to `.env`:

```env
OPENAI_API_KEY=sk-...
```

Then recreate the container to apply it:

```bash
docker compose up -d --force-recreate curia
```

### Web research (Tavily)

Tavily powers the `web-search` skill, which lets agents research topics and look up current information during tasks.

<Steps>
  <Step title="Get a Tavily API key">
    Sign up at [tavily.com](https://tavily.com) and copy your API key from the dashboard.
  </Step>

  <Step title="Set the environment variable">
    Add the key to your `.env`:

    ```env
    TAVILY_API_KEY=tvly-...
    ```

    Then recreate the container:

    ```bash
    docker compose up -d --force-recreate curia
    ```
  </Step>
</Steps>

### Signal messaging

Signal messaging runs via [signal-cli](https://github.com/AsamK/signal-cli). Docker Compose manages the socket path automatically — the only thing you need to provide is your phone number.

<Steps>
  <Step title="Bootstrap signal-cli">
    Signal requires registering a phone number with signal-cli and seeding the `signal-data` Docker volume with the resulting credentials. Refer to your deployment documentation for the bootstrap procedure.
  </Step>

  <Step title="Set the environment variable">
    Set your E.164-formatted phone number — the number you registered via `signal-cli register` and `signal-cli verify`:

    ```env
    SIGNAL_PHONE_NUMBER=+12223334444
    ```

    Do not set `SIGNAL_SOCKET_PATH` — the deployment layer manages this automatically.
  </Step>

  <Step title="Apply the change">
    ```bash
    docker compose up -d --force-recreate curia
    ```

    The Signal channel activates when `SIGNAL_PHONE_NUMBER` is set and the `signal-data` volume is populated.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Setup says my .env already exists">
    This is expected on a second run. `pnpm run setup` never overwrites an existing `.env` — instead it offers a menu to start the stack, resume setup, or do a full reset. Full reset is the only option that regenerates secrets, and it asks for confirmation first.
  </Accordion>

  <Accordion title="Postgres connection refused">
    Confirm the container is running:

    ```bash
    docker compose ps
    ```

    The database password is generated during `pnpm run setup` and shared with the container automatically through `.env`, so the credentials match by default. If you've edited `.env` by hand, make sure `DATABASE_URL` is still consistent with `DB_USER` and `DB_PASSWORD`.
  </Accordion>

  <Accordion title="Email channel not activating">
    All three Nylas variables must be present: `NYLAS_API_KEY`, `NYLAS_GRANT_ID`, and `NYLAS_SELF_EMAIL`. If any are missing, the channel disables itself at startup. Check the startup logs for one of these messages:

    - `NYLAS_API_KEY/NYLAS_GRANT_ID not set — email channel disabled` — the API key or grant ID is missing
    - `NYLAS_SELF_EMAIL not set — email adapter disabled` — the first two variables are set but `NYLAS_SELF_EMAIL` is missing

    Remember to recreate the container after editing `.env`: `docker compose up -d --force-recreate curia`.
  </Accordion>

  <Accordion title="macOS: HTTPS requests fail with 'unable to get local issuer certificate'">
    Node installed via nvm or fnm bundles its own CA store and doesn't trust macOS system certificates. Export your system certs and point Node at them:

    ```bash
    security find-certificate -a -p /System/Library/Keychains/SystemRootCertificates.keychain > ~/.config/curia/macos-ca-certs.pem
    ```

    Then uncomment this line in `.env` and recreate the container:

    ```env
    NODE_EXTRA_CA_CERTS=/Users/yourname/.config/curia/macos-ca-certs.pem
    ```
  </Accordion>
</AccordionGroup>
