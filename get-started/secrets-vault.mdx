title: "Secrets vault"
description: "How Curia stores credentials — an encrypted, database-backed vault that keeps API keys and tokens out of plaintext files and away from the LLM."
---

Curia keeps every credential — LLM API keys, Nylas, Signal, Tavily, the HTTP API token, the console login secret — in an encrypted vault rather than in plaintext `.env` files. The vault is the single source of truth for secrets; tools read from it through a scoped accessor, and the LLM never sees a value.

## How it works

Secrets are encrypted with **AES-256-GCM** and stored in a `secrets` table in Postgres. Each row holds the ciphertext and its initialization vector, never the plaintext. The key that encrypts and decrypts them — `SECRET_ENCRYPTION_KEY` — is the one secret that has to live outside the vault, in `.env`.

At runtime a tool calls `ctx.secret("nylas_api_key")`; the execution layer checks that the tool declared that key, decrypts the value, and hands it to the handler. Every access is audit-logged (which tool, which task, and when), but the value itself is never written to a log.

## What stays in `.env`

Only the four values needed to reach and unlock the vault, plus non-secret deployment config:

| Variable | Purpose |
|---|---|
| `DB_USER` | PostgreSQL user. |
| `DB_PASSWORD` | PostgreSQL password. |
| `DATABASE_URL` | Postgres connection string (where the vault lives). |
| `SECRET_ENCRYPTION_KEY` | Base64-encoded 32-byte AES-256 master key that decrypts the vault. |

`pnpm run setup` generates the database password and the master key, writes them to `.env`, and seeds the core credentials (`anthropic_api_key`, `api_token`, `web_app_bootstrap_secret`) into the vault automatically.

<Warning>
  **Back up `SECRET_ENCRYPTION_KEY`.** It is the only thing that can decrypt the vault. If you lose it, every stored secret becomes permanently unrecoverable and you have to re-seed from scratch. Keep a copy somewhere independent of the server — a password manager or a secrets store.
</Warning>

## Adding vault secrets

Core credentials are seeded by `pnpm run setup`. Channel credentials are managed from **Settings → Channels** in the Curia console — each channel's settings page has a field for its credential (Nylas API key, Signal phone number, Tavily key, etc.). After adding or updating a vault secret, restart Curia so it re-reads the vault on startup:

```bash
docker compose restart curia
```

### Vault key names

| Vault key | Set by |
|---|---|
| `anthropic_api_key` | `pnpm run setup` (prompted) |
| `openai_api_key` | Settings → Channels → Email |
| `openrouter_api_key` | Settings → Channels |
| `api_token` | `pnpm run setup` (generated) |
| `web_app_bootstrap_secret` | `pnpm run setup` (generated, shown once) |
| `nylas_api_key` | Settings → Channels → Email |
| `nylas_grant_id` | Settings → Channels → Email → Email accounts |
| `nylas_self_email` | Settings → Channels → Email → Email accounts |
| `channel.signal.phone_number` | Settings → Channels → Signal |
| `tavily_api_key` | Settings → Channels → Web search |

Channel credentials managed through the [channel registry](/references/channel-config-schema) are stored under namespaced keys following the convention `channel.<name>.<field>` (e.g. `channel.email.nylas_api_key`).

## Rotating the master key

Rotating `SECRET_ENCRYPTION_KEY` re-encrypts every stored secret under a new key. Supply both the old and new keys and the database connection:

```bash
SECRET_ENCRYPTION_KEY_OLD=<old-base64> \
SECRET_ENCRYPTION_KEY_NEW=<new-base64> \
DATABASE_URL=<url> \
pnpm exec tsx scripts/rotate-secret-key.ts
```

Generate a new key with `openssl rand -base64 32`. After rotation, replace `SECRET_ENCRYPTION_KEY` in `.env` with the new value and recreate the container. Keep the old key until you have confirmed the instance comes up cleanly with the new one.

## Tools that require a secret

A tool can declare that a secret must be present before it can be used. Declaring a vault key in the tool manifest's `install.requires_secrets` makes the [registry](/core-concepts/registry) refuse to install or enable the tool until that key is in the vault. The bundled `web-search` tool uses this for `tavily_api_key` — it stays disabled until you provision a Tavily key.
